# Site Ship

Довести статический сайт до продакшена и задеплоить, не переспрашивая по мелочам.

Не для одиночного дефекта интерфейса («дёргается», «не кликабельно») — для этого `web-bugfix-verify`.
Не для правки содержания резюме — для этого `resume-portfolio-edit`.

## Контекст проекта

Пути не угадывать — находить по факту: `git remote -v` в папке, `README`, `index.html`. Типовая раскладка:

| Проект | Репозиторий / прод | Локальная папка |
| --- | --- | --- |
| Сайт-визитка | `<user>/<repo>` → `<user>.github.io/<repo>` | `~/Desktop/<repo>` |
| Сайт-резюме | `<user>/resume` → `<user>.github.io/resume` | `~/Desktop/site-resume` |
| Сайт на своём домене | `example.ru` | `~/Desktop/<project>` |

Повторная отправка того же сообщения — тот же запрос, а не второй заход: не выполнять деплой или правку дважды.

## Порядок

1. **Найти источник правды.** Репозиторий (`git remote -v`), ветка, локальная папка, `git status`, последние 5 коммитов. Не угадывать путь — сверить `README`/`package.json`/`index.html`.
2. **Зафиксировать фактический стек.** Чистый HTML/CSS/JS или сборка? Какие шрифты, иконки, библиотеки подключены? Проверять файлы, а не предположения из брифа.
3. **Редизайн от референса.** Если пользователь дал ссылку/скриншот — извлечь палитру, типографику, сетку и повторить приём, а не копировать контент. Тексты — в тоне заказчика, без «продающих» клише, если это юрист/официальное лицо.
4. **Проверить в браузере до отчёта.** Desktop + мобильный вьюпорт (390px), скролл, клики, консоль, 404 в сети, шрифты, перекрытия. «Готово» без открытой страницы — запрещено.
5. **Коммит и пуш сразу.** Пользователь ждёт `залей на гитхаб` как часть результата: атомарные коммиты, осмысленные сообщения, push в тот же ход. Не спрашивать разрешения на пуш, если он уже просил раньше.
6. **Деплой.** GitHub Pages: нужная ветка/папка, `CNAME` с доменом, DNS (A/AAAA на apex, CNAME `www`), Enforce HTTPS. Проверить прод-URL, а не только локальный файл.
7. **Индексация.** Файлы верификации (`yandex_*.html`, `google*.html`) — в корень сайта, затем sitemap, robots, мета, Open Graph, JSON-LD. Домен без «www» и с «www» должен отдавать один канонический адрес.
8. **Отчёт.** URL, что изменено, что проверено в браузере, что осталось (DNS-ожидание, модерация поисковика).

## Жёсткие правила

- Не выдумывать факты, цены, адреса, телефоны, кейсы. Всё — из файлов или профиля GitHub.
- Фото из папки заказчика не выдавать за товары, которых нет; помечать как референсы, если часть продана.
- Перед массовой правкой — бэкап затрагиваемых файлов (копия рядом или ветка).
- Не ломать существующие секции и SEO-разметку; удаление формы/блока — только с зачисткой стилей и обработчиков.
- Ответ пользователю — по-русски.

## Проверки перед «готово»

- Прод-URL открывается по HTTPS, без редиректа на 404.
- Мобильная версия: стрелки, галереи и «бегущие строки» не дёргаются и не являются стикерами.
- Ссылки в галерее кликабельны, если это не заявленное перетаскивание.
- В консоли нет ошибок, в сети нет 404 на ассеты.
