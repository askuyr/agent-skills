# OpenCode Config

Правки конфигурации OpenCode с бэкапом и проверкой, без утечки ключей в чат.

## Где что лежит (Windows)

- Конфиг: `%USERPROFILE%\.config\opencode\opencode.jsonc` (`C:\Users\<user>\.config\opencode\opencode.jsonc`)
- Глобальные команды: `%USERPROFILE%\.config\opencode\commands\`
- Глобальные скиллы: `%USERPROFILE%\.agents\skills\` (читается OpenCode), плюс `%USERPROFILE%\.config\opencode\skills\`
- История сессий: `%USERPROFILE%\.local\share\opencode\opencode.db` (SQLite)

## Порядок

1. **Прочитать текущий конфиг** и не ломать существующие блоки. Сохранить бэкап с датой: `opencode.jsonc.bak-<тема>-<timestamp>`.
2. **Провайдер.** Блок `provider` с `npm`, `options.baseURL`, `options.apiKey`, `models`. Ключ — через `{env:VAR}` или в конфиг, но **никогда не печатать его в ответе**.
3. **Проверить.** `opencode --version` — базовый признак, что CLI жив. `opencode models` в этой среде падает с `Database is not empty and has no session table` (БД занята запущенной TUI или CLI не может её открыть), поэтому список моделей надёжнее смотреть в TUI-пикере моделей или после полного перезапуска OpenCode. Пробный запрос дешевле, чем догадки: одна короткая сессия на новой модели.
4. **Дешёвая модель.** Смотреть цену за 1M токенов в каталоге провайдера; отдельно проверять кэш-ридинг. Не обещать экономию без цифр.
5. **Плагины.** Поле `plugin` (npm-пакеты), после установки — перезапуск; проверить, что OpenCode стартует и сессия открывается.
6. **Скиллы.** `npx -y skills@latest add <owner>/<repo> -g -a opencode -s '*' -y` (или `--all`), затем проверить `npx skills ls -g -a opencode`.
7. **Отчёт:** что изменено, где бэкап, как проверить, нужен ли рестарт.

## Правила безопасности

- Ключи из истории чата считаются скомпрометированными: рекомендовать отзыв и перевыпуск.
- Не писать ключ в файлы проекта, логи, коммиты.
- Перед экспериментами с провайдерами — бэкап конфига; после — проверка, что текущая модель не сломана.
- Ответ — по-русски, без вывода секретов даже в «маскированном» виде.
