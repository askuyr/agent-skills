# Resume / Portfolio Edit

Резюме и портфолио — про факты и подачу, а не про генерацию «красивого» текста.

## Жёсткие правила

1. **Не выдумывать** проекты, метрики, технологии, сертификаты, должности. Всё добавляемое должно быть подтверждено файлом в папке проекта, профилем GitHub или прямым сообщением пользователя.
2. **Не удалять** несвязанные части резюме и портфолио. Удаление — только по прямому указанию («убери сертификаты», «убери баннер»).
3. **Бэкап** затрагиваемых файлов перед правкой; работа в отдельной ветке, коммиты атомарные.
4. **Контакты сверять** с источником: телефон, почта, город. В истории бывают опечатки — переспросить цифру, а не «исправить» наугад.
5. **Убирать следы нейрогенерации**: одинаковые карточки, «носители», стоковые формулировки, англицизмы ради англицизмов.
6. **Тон**: продающий, но без клише и гарантий результата; для юриста/чиновника — сдержанно-официально.
7. Ответ — по-русски.

## Порядок

1. Найти папку проекта (исходники, референс, портфолио) и папку сайта, репозиторий `<user>/resume`. Прочитать резюме, референс, портфолио, `README`, профиль GitHub.
2. Составить список фактов: образование, опыт, проекты, стек, достижения — с источником для каждого.
3. Правки текста: убрать «слоганы», раскрыть размытые формулировки, упростить перегруженные конструкции. Ничего не сокращать без причины.
4. **Сборка:** PDF (одна страница — если просили) и/или статический сайт на GitHub Pages. Сайт и деплой — по скиллу `site-ship`; здесь только содержание.
5. Проверка: все ссылки открываются, телефоны/почта верные, фото на месте, мобильная версия не разъезжается.
6. Отчёт: что перенесено, что удалено и почему, что не подтверждено и осталось за пользователем.

## Частые ошибки

- «Улучшение» текста с добавлением несуществующих метрик («ускорил на 40%»).
- Превращение учебного проекта в «коммерческий опыт».
- Оставить сертификаты «планирую получить» как полученные.
- Вставить чужие фото/кейсы с Pinterest как свои работы.
