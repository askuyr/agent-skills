# Программа мероприятия

Программа — это арифметика, а не список красивых названий. Один раз собрал — дальше любая правка проверяется на стыковку с афишей и формой.

## 0. Источник правды

Название мероприятия, дата, адрес и дедлайн — из последней афиши. Названия секций и спикеры — из брифа организатора. Не придумывать секции и не менять формулировки «для красоты»: они уже напечатаны на афише.

## 1. Каркас дня

Обычный форум/конференция:

| Блок | Длительность | Примечание |
|---|---|---|
| Регистрация и кофе | 60 мин | до официального начала |
| Приветствие | 10–15 мин | модератор + 1–2 лица |
| Пленарное заседание | 60–90 мин | один трек, без параллелей |
| Панельные дискуссии | 60–90 мин | могут идти параллельно |
| Молодёжная/тематическая секция | 60–120 мин | параллельный трек |
| Кофе-брейк | 20–30 мин | реально 20, в программе 30 |
| Вечерняя программа | 60 мин | награждение, концерт |
| Торжественное закрытие | 10 мин | последним |

Мероприятие на 3–4 часа — не больше 4 блоков, иначе программа превращается в список.

## 2. Правила, которые ловят 90% ошибок

- **Время складывается**: сумма блоков = заявленное начало и конец. Считать, а не на глаз.
- **Пленарное не пересекается** ни с чем; параллельные треки помечать явно («параллельно с…»).
- **Запас 10 минут** между блоками на переходы; в программе не показывать, в расчёте держать.
- **Один формат времени** во всех документах: `10:00–10:30` (не `10.00 до 10.30` в одном месте и `10:00` в другом).
- **Одно название блока** — в афише, программе, форме и постах. Расхождение ищется поиском по папке мероприятия, а не памятью.
- Регистрация не «до 9:00», а «с 9:00 до 10:00», если люди реально приходят в это окно.

## 3. Что отдать

1. `program.md` — таблица блоков: время, название, формат, спикеры, зал/трек.
2. `program.html` — та же таблица в стилистике афиши (`--bg`, `--accent`, `--h1`), A4 для печати и мобильная версия.
3. Блок «Программа» для афиши — только время и названия, без спикеров, если их больше трёх.
4. Строка-анонс для поста: дата, время, адрес, «вход по регистрации» + ссылка на форму.

## 4. Проверка перед публикацией

- сумма времени сходится с началом и концом;
- нет двух блоков в одном зале одновременно (кроме помеченных параллельных);
- названия совпадают с афишей (`afisha_*.html`) и формой (`yandex-form-event`);
- закрытие последнее, кофе-брейк не последний;
- дата и день недели правильные (проверить по календарю, не по памяти).

## 5. Правка программы

Правка идёт в `program.md` → потом в HTML → потом проверка афиши и формы. После каждой правки сказать, какие файлы разъехались: «время в афише осталось 10:30, обновить?» — а не молча оставить расхождение.
