# Редизайн по референсу

Референс задаёт приём, а не контент. Цель — сайт, в котором человек находит нужное с первого экрана, а не «нафаршированный» лендинг.

## Что уже пошло не так (из истории)

- «добавь кучу фишек, чтобы сайт был нафаршированный» → «он просто неудобный, длинная залупа, разбей по отдельным страницам, слишком много лишнего».
- «редизайн с 0» без разбора референса → следующий заход «что-то похоже но не точ в точ».
- Правки шли волной мелких итераций (30+ сообщений в одной сессии) вместо одного разобранного макета.

Вывод: сначала структура и объём, потом украшения. Фишки — дозированно и по одной странице.

## Порядок

1. **Снять факты о проекте.** `git status`, remote, ветка, стек (чистый HTML/CSS/JS или сборка), какие страницы и секции уже есть. Без этого «с нуля» = потеря SEO и рабочих блоков.
2. **Разобрать референс** (картинка или URL): сетка и ширина контейнера, вертикальный ритм, 3–5 HEX-цветов, шрифты и их размеры, приёмы (крупный заголовок, тонкие линии, много воздуха, фото в полный рост). Записать токенами: `--bg`, `--fg`, `--accent`, `--muted`, `H1/H2/body`, отступы.
3. **Согласовать карту страниц** — одной таблицей: страница → 3–5 блоков → чем закрывает задачу. Один смысл = одна страница. Длинную простыню резать на: главная, услуги/работы, о себе, контакты.
4. **Собрать каркас без украшений:** типографика, сетка, отступы, состояния ссылок. Сначала читаемость на 390px и 1440px.
5. **Добавить оформление по одному блоку**, сверяя с референсом на каждом шаге. Каждый новый эффект отвечает на вопрос «помогает найти/прочитать?», иначе не добавлять.
6. **Проверить в браузере до отчёта:** desktop + 390px, консоль, 404 в сети, шрифты загрузились, ничего не перекрывается, клавиатурный фокус виден, `prefers-reduced-motion` не ломает анимации.
7. **Зафиксировать:** коммит в рабочей ветке, затем `site-ship` для домена, индексации и прода.

## Контент

- Тексты — в тоне владельца: юрист/политик — сдержанно, без «продающих» клише; магазин — конкретика по товарам.
- Не выдумывать цифры, награды, кейсы. Не выдавать фото из папки за проданные товары.
- Правки содержания (заголовки, порядок секций, даты) — отдельная итерация: менять текст, не переделывая вёрстку, если не просили обратное.

## Жёсткие правила

- Бэкап: ветка `backup-<дата>` или копии затрагиваемых файлов до массовой правки (см. `git-remote-ops`).
- Не ломать существующие секции и SEO-разметку; удаление блока — только с зачисткой стилей и обработчиков.
- Не отчитываться «готово» без открытой страницы.
- Один вариант — один файл/ветка; не перезаписывать принятый вариант.
- Ответ — по-русски.
